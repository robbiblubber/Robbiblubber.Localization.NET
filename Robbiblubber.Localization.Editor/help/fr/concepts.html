Notions de base

Cette page explique comment une application trouve ses textes et ce que cela implique pour les fichiers que vous modifiez.

Langues

Une langue peut aussi être propre à une région. Chaque langue a une courte clé, par exemple en pour l'anglais, de pour l'allemand ou de-AT pour l'allemand d'Autriche. Une définition de langue (.locale) décrit une langue : sa clé, son nom tel qu'il est présenté à l'utilisateur, ses icônes et quelques réglages. Voir Définitions de langue.

Une langue peut avoir une langue de base. Une langue de-AT basée sur de n'a besoin que des textes qui diffèrent en Autriche ; tous les autres textes sont repris de de.

Tables de langue

Une table de langue (.ltab ou .cltab) contient les textes d'une langue pour une application ou une partie de celle-ci. Le champ Langue de l'en-tête indique à quelle langue appartiennent les textes. Une application a généralement une table par langue, par exemple app.en.ltab, app.de.ltab et app.fr.ltab, chacune avec les mêmes symboles.

Symboles et textes

Chaque entrée d'une table a un symbole et un texte. Le symbole est le nom sous lequel l'application demande un texte ; il est identique dans toutes les langues. Le texte est la traduction. Les symboles se composent généralement de mots séparés par des points, par exemple menu.file.open ou message.saved. Les majuscules et les minuscules comptent : Save et save sont deux symboles différents.

Préfixes

Le préfixe permet de distinguer les symboles de différentes applications ou de différents composants. L'application demande un texte sous la forme prefix:symbol, par exemple app:menu.file.open. Dans la table, vous saisissez uniquement le symbole (menu.file.open), et le préfixe une seule fois dans l'en-tête. Une table avec plusieurs préfixes fournit ses symboles sous chacun d'eux ; une table sans préfixe les fournit tels quels.

N'écrivez pas le préfixe devant les symboles dans la table. L'éditeur signale ces lignes comme un problème, car la table place déjà son préfixe devant eux.

Espaces réservés

Les textes peuvent contenir des espaces réservés : un $ suivi d'un nom en majuscules, par exemple $NAME dans $NAME has been saved. L'application les remplace par une valeur. Conservez les espaces réservés tels quels lorsque vous traduisez un texte ; vous pouvez les déplacer à un autre endroit de la phrase.

Touches d'accès

Dans les textes des menus, des boutons et des libellés, un & désigne la lettre qui est soulignée et peut être utilisée avec Alt, par exemple &Open.... Dans un même menu ou une même fenêtre, chaque lettre ne devrait être utilisée qu'une seule fois. Pour afficher un &, écrivez &&.

Que se passe-t-il si un texte manque ?

Si la table de la langue actuelle ne contient pas un symbole, l'application utilise le texte de la langue de base ou un texte intégré à l'application, généralement le texte anglais. Une entrée manquante ne provoque donc pas d'erreur, mais l'utilisateur voit un texte non traduit.

Si le même symbole apparaît deux fois pour la même langue, c'est le dernier qui l'emporte. L'éditeur vous signale ces doublons, aussi bien dans la table qu'à l'ouverture d'un fichier.
